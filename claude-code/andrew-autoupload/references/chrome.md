# Claude Code + Claude in Chrome 경로

현재 플랫폼 파일럿은 미완료다. Claude Code와 연결된 Chrome 도구만 사용한다.

## 연결

START.md의 플랜·버전·/login 전제를 확인한다. 사용자가 `/chrome`에서 상태 확인·Reconnect extension·브라우저 선택을 할 수 있다. 도구 목록은 `/mcp` → claude-in-chrome → View tools에서 확인한다. 실제 스키마가 없는 도구를 만들어 호출하지 않는다.

## 첨부

1. 세션이 읽을 수 있는 로컬 이미지 경로를 확인한다. 공식 문서상 Claude Code 2.1.211+에서 업로드를 지원하며 총 10MB 이내, 다중 하드링크 금지다. 하드링크 파일은 허용된 폴더의 일반 복사본을 사용한다. 원본 경로만 가능하다고 단정하지 않는다.
2. 로컬 테스트 폼부터 시작한다. 로컬 URL이 제한되면 assets 폴더만 127.0.0.1에 제공하는 임시 서버를 사용할 수 있다. 클라우드나 제3자 폼에 테스트 파일을 보내지 않는다.
3. 파일 선택창 버튼을 누르지 않고 현재 폼의 input type=file을 찾는다. 실제 도구 목록에 `find` / `file_upload`가 있으면 각각 제공된 스키마를 따른다. 사용자 제공 스킬의 예시는 file_upload의 ref와 paths지만 현재 스키마와 일치하는지 확인한 뒤 사용한다.
4. 파일을 입력에 연결하고 실제 미리보기를 확인한다. 성공 도구·인수·버전·파일 경로 조건을 .preflight.json에 남긴다.
5. 실제 사이트에서는 현재 게시물의 입력인지 확인 후 같은 방법을 쓴다. 인스타그램은 비율·잘림을 확인하고 캡션 입력 후 공유 직전 멈춘다.

ego lite 경로에서는 그 스킬의 uploadFile 헬퍼로 같은 원칙을 지킨다. 선택창 버튼을 누르지 않고 폼의 file input에 직접 연결한 뒤 미리보기를 확인한다.

파일 첨부 기능이 없으면 이미지·원고를 저장하고 필요한 수동 첨부만 요청한다. OS 파일 선택창, 데스크톱 좌표 제어, 원본 스킬의 마지막 공유 단계로 전환하지 않는다.

## 막혔을 때

- 미연결: 확장 활성화·버전·Chrome 실행 → /chrome 재연결 → 필요 시 앱·Chrome 재시작.
- 읽기만 가능: 계획 모드에서는 상태 변경 승인이 별도로 필요할 수 있다. 사이트 권한과 승인 대기를 확인한다.
- 파일만 실패: Read 권한·10MB 한도·하드링크 여부를 확인한다. Codex의 파일 URL 설정을 필수 처방으로 복사하지 않는다.
- 네이버만 실패: 실제 오류 문구를 그대로 기록한다. 이동이 시작되기도 전에 거부되고 문구가 safety restrictions 계열이면 확장의 도메인 분류이므로 SKILL.md의 ‘브라우저 경로 선택’을 따른다. IP 차단이나 모델 문제로 단정하지 않으며, 사이트 권한 승인으로 풀 수 있다고 안내하지 않는다.
- /clear로 작성 탭이 사라질 수 있다. 로컬 원고를 보존하고, 인스타그램은 새 작성 화면에 재첨부·재입력한다.

도구가 확인되기 전에는 예시 이름을 호출 가능한 기능으로 취급하지 않는다. 플랫폼 성공 여부는 VALIDATION.md에 실측 결과만 기록한다.

[공식 연결·첨부·문제 해결](https://code.claude.com/docs/en/chrome)

명시적인 URL 보안 정책·권한 거부가 나오면 로컬 서버나 다른 URL로 같은 접근을 재시도하지 않는다. 도구를 바꾸는 것도 기본은 금지이며, 유일한 예외는 SKILL.md ‘브라우저 경로 선택’이 정한 ego lite 경로다. 그 경로를 쓸 수 없으면 사용자에게 오류를 그대로 보고하고 가능한 원고 작업만 계속한다. 위 임시 서버는 정책 거부가 아닌 정상 지원 환경에서의 로컬 테스트 제공 방법이다.
