# 파일럿 검증 기록

상태: macOS 로컬 Codex + 연결된 Chrome 확장에서 Instagram 이미지 첨부와 캡션 입력 화면 도달, Naver Blog 이미지 첨부를 검증했다. 캡션·블로그 제목·본문 입력, 임시저장, 공개 발행은 실행하지 않았다. 아래 미확인 항목은 지원을 뜻하지 않는다.

| 항목 | 실제 기록 |
|---|---|
| OS·버전 | macOS 로컬 세션. 정확한 OS 버전은 기록하지 않음 |
| 계정 플랜 | 미확인 |
| 앱·확장 버전 | 미확인 |
| 브라우저·도구명·호출 인수 | Codex Browser Use의 연결된 Chrome 확장. `waitForEvent("filechooser")` → 화면의 `컴퓨터에서 선택` 클릭 → `chooser.setFiles([원본 절대경로])` |
| 파일 접근 경로·용량 조건 | 이미지 생성 도구가 반환한 `$CODEX_HOME/generated_images/...` 원본 PNG, 1122×1402, 1,734,961바이트 성공. 프로젝트 사본은 내용이 같지만 업로드 경로로 시험하지 않음 |
| 로컬 폼 첨부·텍스트 입력 | Chrome 확장의 파일 URL 액세스 허용 전후 모두 `file://` 방문이 Browser Use URL 정책으로 거부됨. 실제 사이트 검증과 별개로 기록 |
| OS 파일 선택창 미사용 | chooser 이벤트와 `setFiles`로 첨부했으며 네이티브 파일 선택창을 직접 조작하지 않음 |
| 네이버 본문 구조·첨부·임시저장 | `mainFrame` 안의 스마트에디터와 제목·본문 문단 구조를 확인. `사진 추가` 클릭 전에 chooser 대기 → 원본 PNG `setFiles`로 첨부하고 이미지 파일명·대표 상태를 확인. 제목·본문 입력과 임시저장은 미실행 |
| 인스타그램 첨부·캡션·잘림 확인 | 게시물 전용 입력 확인, 원본 PNG 첨부, 자르기 미리보기, `원본` 비율, 편집 단계, 캡션 입력 화면 `0/2200` 도달 확인. 캡션은 입력하지 않음 |
| 화면 보존·중단 후 재개 | 캡션 입력 화면을 다음 작업 턴에서 다시 읽어 동일 상태를 확인함 |
| 최종 공개 발행 미실행 | `공유하기` 버튼을 누르지 않음 |

로컬 폼과 실제 플랫폼 검증은 서로 다른 결과로 취급한다. 로컬 `file://` 방문 실패만으로 사용자가 승인한 HTTPS 작성 화면의 chooser 검증을 차단하지 않는다. 개인 계정 정보 없이 성공한 범위만 기록하고, 다른 OS·플랜으로 확대하지 않는다.

숨은 파일 입력을 강제로 클릭하는 방식은 파일 chooser 이벤트가 발생하지 않아 시간 초과됐다. 상태를 확인한 뒤 화면의 `컴퓨터에서 선택` 버튼을 클릭하는 문서화된 방식으로 1회 재시도했고 성공했다. 이 차이를 Codex Chrome 절차에 반영한다.
